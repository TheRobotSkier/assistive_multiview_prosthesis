# Iteration 23 — Fix crash-to-continuous Pipeline by repairing Python entry-point scripts

## What was observed in the logs

### Replay test results (`logs/replay-results/replay_20260617_061201/`)

- `bag_analysis.txt` showed both `gtsam_tracker_node` and `sift_feature_node` **immediately crashed** after launch with `PackageNotFoundError` (gtsam_tracker) and `ModuleNotFoundError` (cross_camera_features).
- `log_analysis.txt` confirmed: **"No logs recorded for these nodes"** — the nodes never published a single message and died before the bag replay produced /camera_info messages.
- Downstream nodes (tsdf_node, registration_node) were STALLED waiting for `/gtsam_odometry` and `/features_3d` that never arrived. The entire pipeline was effectively dead.
- `bag_metrics.json`: The only non-zero entries were from the raw VIO bag topics (`/camera_info` at 0.01 Hz, `/camera0/camera_info` at 0.35 Hz). All GTSAM and cross-camera topics were at 0.0 Hz.

### Unit test results (`logs/test-results/`)

- `gtsam_tracker.xml`: 8 test failures — all `RCLError: error creating node`. The ROS 2 node creation crashes because the entry-point script (`gtsam_tracker_node`) fails at import time with `PackageNotFoundError`, so test fixtures that try to launch the node also crash.

### Previous iteration context (iteration-logs/)

- **Iteration 21**: Fixed `PackageNotFoundError` by splitting `setup.py` packages → py_modules to avoid namespace collisions. Also added lazy imports in `sift_feature_node.py`.
- **Iteration 22**: Changed `console_scripts` entry_points → raw `scripts=` in setup.py to bypass pkg_resources load_entry_point path.
- **Root cause (diagnosed here)**: Neither fix ever took effect because the auto-iterate loop runs `make test-unit` without first running `colcon build`. Packaging changes (`setup.py`, new script files in `scripts/`) are never deployed to the install space, so the OLD entry-point wrappers (generated by a pre-setuptools72 build) remain in place and crash.

## What was decided to work on

**Problem**: The two core Python packages (`gtsam_tracker`, `cross_camera_features`) are broken in the install space. The old entry-point scripts use `pkg_resources.load_entry_point()` which chokes because the dist-info metadata is missing (setuptools82+ incompatibility during the initial `make build`). The fix from iterations 21 and 22 never deployed because the auto-iterate loop never runs a rebuild.

**Fix strategy**:
1. Downgrade setuptools from 82+ to 71.1.0 inside the container so `colcon build` works with `setup.py` packages correctly.
2. Perform a clean `colcon build --symlink-install` for the two packages so proper dist-info metadata and entry-point scripts are generated.
3. Modify `scripts/auto_iterate.sh` to always rebuild these packages before unit tests so future packaging changes take effect immediately.

## What was changed

### 1. `scripts/auto_iterate.sh:229-240` — Added pre-test build step

```bash
# ---- Build Python packages before test ----
log "Building Python packages (gtsam_tracker, cross_camera_features)..."
"$backend" exec --user prosthesis prosthesis /bin/bash -lc \
    'source /opt/ros/jazzy/setup.bash && \
     cd /prosthesis_ws && \
     colcon build --packages-select gtsam_tracker cross_camera_features \
       --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release 2>&1' \
    >>"$FORGE_LOG_DIR/unit_test_step_${step}_attempt_${attempt}.log" 2>&1 || \
    log_warn "Python package build had issues (non-fatal)"
```

This ensures that in every future iteration, the latest source changes (including packaging/setup.py changes) are built and symlink-installed into the install space **before** unit tests or replay tests run. The `|| log_warn` makes the build non-fatal — if colcon fails (e.g., setuptools version issue again), the unit tests will still run and fail with a clear error.

### 2. Container-side: `pip3 install "setuptools<72" --break-system-packages`

Downgraded setuptools from 82.x → 71.1.0, which is compatible with `setup.py`-based packages and `entry_points`/`scripts` in colcon. Without this, `colcon build` fails with `Error in gtsam_tracker setup.py: package must be installed ...`.

### 3. Container-side: Clean rebuild of gtsam_tracker and cross_camera_features

```
colcon build --packages-select gtsam_tracker cross_camera_features \
  --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
```

This:
- Created proper `.dist-info/METADATA` with version 0.1.0
- Generated correct entry-point scripts that directly import the module (`from gtsam_tracker.gtsam_tracker_node import main`) — no more `EASY-INSTALL-ENTRY-SCRIPT` wrappers
- Symlinked source → build → install so future Python-only changes take effect immediately without rebuilding

## Expected impact

1. **Immediate fix**: `gtsam_tracker_node` and `sift_feature_node` now start correctly. Verified both nodes when run via `ros2 run` produce their expected `main()` execution (no more `PackageNotFoundError` or `ModuleNotFoundError`).

2. **Pipeline unblocks**: With these nodes working, the TSDF fusion node receives `/gtsam_odometry` and `/features_3d` topics, enabling the full pipeline to run. This is the foundation for all downstream optimization goals (lower trajectory RMS, better fused pointclouds).

3. **No more staleness**: The auto-iterate build step ensures that packaging changes in future iterations are immediately deployed. The `|| log_warn` makes it safe — if the build fails for any reason, tests still run and catch the error.

4. **Develop-install efficiency**: Because `--symlink-install` is used, Python-only changes (the majority of our edits) take effect immediately without any rebuild. The build step is only needed when `setup.py` changes or new script files are added.
