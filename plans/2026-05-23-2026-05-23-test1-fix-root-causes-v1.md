## Implementation Plan

### Phase 1: Fix Score Sweep (CRITICAL)

The Rust `OnceLock<RuntimeConfig>` at `runtime_config.rs:240` caches the config on first access. The sweep sets `GRASP_CONFIG_PATH` and creates a new `GraspLibrary()`, but the `.so`'s static state persists. **All sweep iterations use 20K samples.**

- [ ] **1.1** Add a `reload_config()` C API function to `c_api.rs` that calls `RUNTIME_CONFIG.take()` to clear the OnceLock, forcing a reload on next `get()` call
- [ ] **1.2** Expose `reload_config` through `ffi_bridge.py` as `lib.reload_config()`
- [ ] **1.3** Call `sweep_lib.reload_config()` after setting `GRASP_CONFIG_PATH` in the sweep loop (before creating the new library)
- [ ] **1.4** Verify sweep produces different latencies at different sample counts (1K should be ~5ms, 100K should be ~300ms)

### Phase 2: Rotate Hand Approach 45° on Z-Axis

The current approach is straight along +X. The wrist camera (looking +X from 16cm above) sees the SAME face as the head camera (looking down from above). Rotating the hand 45° on Z means:
- The wrist camera now sees a DIFFERENT face (45° rotated view)
- More of the object surface becomes visible to the wrist camera
- The multi-view advantage should increase for non-convex objects

- [ ] **2.1** Update `hand_approaches.py`: rotate all approach poses 45° around Z-axis (qx=0, qy=0, qz=sin(π/8), qw=cos(π/8)). Adjust px/py to keep the hand at ~15cm from object center along the new approach direction

## Verification Criteria

1. **Sweep produces different latencies**: 1K samples < 10ms, 100K samples > 200ms
2. **Sweep produces different scores**: 1K samples have lower mean score than 100K samples
3. **Object gallery shows no interior points**: all objects appear as thin shells
4. **Per-view coverage clearly shows complementary views**: head sees top, wrist sees side
5. **Intent Precision Δ ≥ +5%** (improved from +1.3% with rotated approach)
6. **Latency P95 ≤ 100ms** (maintained with early termination)

## Potential Risks and Mitigations

1. **OnceLock.take() requires unstable feature or Rust 1.80+**
   Mitigation: Use `std::sync::OnceLock::take()` (stable since Rust 1.80). If unavailable, use `std::sync::atomic` to store a "dirty" flag that forces re-reading the config file.

2. **Rotated approach may not improve Δ for convex objects**
   Mitigation: The improvement is expected primarily for non-convex objects. Convex objects may show no change. This is physically correct.

3. **SQ wireframe overlay may be too complex for the gallery figure**
   Mitigation: Start with a simple approach — plot 3 ellipsoid cross-sections (XY, XZ, YZ planes) as colored curves overlaid on the point cloud. This is much simpler than a full wireframe.

4. **Early termination threshold too aggressive**
   Mitigation: Use 0.15m threshold (conservative). The maximum finger reach is ~8cm, so 15cm gives 7cm margin. Verify by checking that no Tier 1 grasps are missed.

## Alternative Approaches

1. **For the OnceLock issue**: Instead of modifying the Rust API, run the sweep as separate subprocess invocations with different `GRASP_CONFIG_PATH` values. This avoids any Rust changes but is slower and more complex.

2. **For the rotated approach**: Instead of rotating all objects 45°, use per-object approach angles that maximize the wrist camera's view of the non-occluded face. This is more realistic but requires per-object tuning.
