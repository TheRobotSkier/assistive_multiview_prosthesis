# Plan: Update TSDF Report Figures

## Objective

Modify the two TSDF cross-section figures (`tsdf_unsigned_cross_section.png` and `tsdf_signed_cross_section.png`) generated by `report/generate_figures.py` to:

1. **Unsigned figure**: Add the superquadric surface contour overlay and remove the ROI bounding box so the object fills more of the frame.
2. **Signed figure**: Add the full set of ROI point cloud observations (all ~964 points) projected onto the 2D cross-section, so the reader can see how the complete set of surface observations relates to the signed distance field and the SQ contour.

---

## Implementation Plan

### 1. Helper: Project 3D Points to Cross-Section

- [ ] Add a helper function `_project_points_to_slice(points_3d, z_mid, z_width)` that filters point cloud points within a configurable Z-band (default: entire ROI depth) and plots their X,Y positions on the 2D cross-section.
  - **Rationale**: The current point cloud rendering clips to ±2 voxels of the cutting plane, hiding the full spatial extent of the observations. A wider Z-band (or the full ROI depth) shows where all observations lie relative to the SQ surface.
  - **Approximation option**: If showing all points creates too much visual clutter, use a 2D Gaussian kernel density estimate (via `scipy.stats.gaussian_kde` or a manual 2D histogram) over the projected point locations to produce a density heatmap — this gives the spatial distribution without individual point clutter.

### 2. Modify `fig_tsdf_unsigned_cross_section`

- [ ] Remove the ROI bounding rectangle (`plt.Rectangle` call and `ax.add_patch`).
  - **Rationale**: The ROI box adds visual noise and constrains the axis limits, preventing the object and its distance field from filling the frame.
- [ ] Set tighter axis limits. After removing the ROI box, the axis limits default to the image extent (which matches the TSDF grid bounds). This is already what `ax.imshow(extent=...)` provides, so no additional axis changes needed — the ROI removal alone lets the viewer zoom in naturally.
- [ ] Add the superquadric surface contour overlay, identical to the signed figure: evaluate `_sq_eval_grid` on a 100×100 grid at the middle Z-slice and draw a `contour(X, Y, F, levels=[0])` in cyan with 2.5 linewidth.
  - **Rationale**: Adding the SQ contour to the unsigned figure helps the reader see how the fitted primitive relates to the unsigned distance field and the observed point cloud at the same cutting plane.

### 3. Modify `fig_tsdf_signed_with_sq`

- [ ] Replace the thin Z-slice point cloud rendering with the full set of ROI points projected onto the cross-section. Use the `_project_points_to_slice` helper with a wide Z-band (e.g., the full ROI height, or ±5 cm) to show all ~964 observations.
  - **Rationale**: The current figure shows <50 points from the thin Z-slice. The reader cannot see the full spatial extent of the surface observations. Showing all points (even projected) reveals the complete surface coverage and helps evaluate how well the SQ contour matches the observations.
- [ ] Adjust point marker size and alpha to avoid visual clutter with ~964 points (suggested: `s=2`, `alpha=0.4`).
  - **Rationale**: Smaller, more transparent markers prevent the point cloud from obscuring the TSDF distance field and the SQ contour.
- [ ] (Optional) If clutter is still an issue, switch to a 2D density heatmap as the "approximation" fallback mentioned in the request.

### 4. Regenerate Both Figures

- [ ] Run `python report/generate_figures.py` to re-generate both `tsdf_unsigned_cross_section.png` and `tsdf_signed_cross_section.png` with the changes above.
  - **Rationale**: Produces the ready-to-use figures for insertion into the report.

## Verification Criteria

- **Unsigned figure**: ROI bounding box is absent; SQ surface contour (cyan line) is visible; title and colorbar remain correct; the object distance field occupies more of the frame.
- **Signed figure**: All ~964 point cloud observations are visible as projected dots or a density overlay; the SQ contour and TSDF signed distance field are still clearly legible; markers are small enough not to obscure the underlying voxel data.
- **No regressions**: The grasp pose overview figure (`grasp_poses_overview.png`) is unchanged.

---

## Potential Risks and Mitigations

1. **Point cloud projection clutter** — 964 points projected onto a small (16×14 voxel) cross-section may overlap heavily.
   - **Mitigation**: Reduce marker size (`s=1.5–2`), use low alpha (`0.3`), and consider jitter or density heatmap as fallback.

2. **SQ surface does not intersect the Z-slice** — The fitted SQ's volume might not intersect the chosen middle Z-slice, producing no visible contour line.
   - **Mitigation**: Compute the SQ's Z-range from `sq_params['translation'].z ± sq_params['c']` and warn/fall back to a nearby Z-slice that does intersect the SQ.

3. **Signed figure becomes too dense to read** — The combination of signed distance field + SQ contour + full point cloud + camera marker may produce visual overload.
   - **Mitigation**: Offer a 2D histogram (50×50 bins on the cross-section) as the density approximation, overlaid with low opacity, so the distance field remains the primary visual layer.

## Alternative Approaches

1. **Separate panel for projected points**: Instead of overlaying all points on the signed cross-section, create a separate side-by-side panel showing only the X-Y projection of the point cloud with the SQ contour. This keeps the signed distance field panel clean while still providing the spatial context.

2. **Interactive figure**: Present the signed figure as a multi-selectable overlay (SQ on/off, points on/off). Out of scope for static report figures, but could be noted for the digital version.

3. **3D isometric view for the signed figure**: Replace the 2D cross-section with a 3D isometric view of the TSDF surface (using marching cubes) with the point cloud and SQ mesh overlaid. This gives a more intuitive spatial understanding at the cost of losing the quantitative signed-distance colorbar.
