# Plan: Update TSDF Report Figures

## Objective

Modify the two TSDF cross-section figures generated by `report/generate_figures.py`:

1. **Unsigned figure**: Add the superquadric surface contour overlay; remove the ROI bounding box so the object fills more of the frame.
2. **Signed figure**: Add the ROI-defining samples (motion model predicted hand poses) projected onto the cross-section, to illustrate how the ROI bounding box relates to the predicted hand trajectory.

---

## Background: What "ROI Samples" Are

The ROI is computed by `predict_roi_with_samples` in `predictor.rs:612-627`:

1. `sample_future_poses` generates **20,000** hand pose samples from the motion model (twist × time horizon)
2. `project_index_tips` projects each sample's index fingertip into world coordinates
3. `compute_prediction_aabb` computes an AABB around these projected points, inflated by `hand_radius = 0.05 m`
4. The resulting AABB is the ROI used for TSDF construction

The ROI samples themselves (`_samples_for_roi` in `c_api.rs:395`) are **discarded** — not stored in the debug dump. However, `sample_initial_particles` (`predictor.rs:269`) is documented as **"equivalent to `sample_future_poses`"** — same distribution, same motion model parameters. The iteration-0 scored_grasps (which are `sample_initial_particles` results) are therefore an **exact proxy** for the spatial distribution of the actual ROI samples.

## Implementation Plan

### 1. Helper: Project Hand Base Positions to Cross-Section

- [ ] Add a helper function `_project_grasp_samples_to_slice()` that:
  - Reads the `scored_grasps` pose translations (`pose_4x4[:, :3, 3]`) from the dump
  - Filters to iteration 0 (`smc_iteration == 0`) — these are the broad initial samples from the motion model prior, directly equivalent to the ROI-generating samples
  - Randomly subsets to ~1,000 points (to avoid visual clutter from 20,000 overlapping points)
  - Returns X, Y arrays for plotting on the 2D cross-section
  - **Rationale**: Using iteration-0 scored_grasps gives real (not synthetic) hand pose positions from the same distribution as the ROI-generating samples, with zero pipeline changes required.

### 2. Modify `fig_tsdf_unsigned_cross_section`

- [ ] Remove the ROI bounding rectangle (`plt.Rectangle` block).
  - **Rationale**: The ROI box adds visual noise and constrains the axis limits. The `ax.imshow(extent=...)` already bounds to the voxel grid, so the object distance field naturally fills the frame.
- [ ] Add the superquadric surface contour: evaluate `_sq_eval_grid` on a 100×100 grid at the middle Z-slice and draw `contour(X, Y, F, levels=[0])` in cyan (linewidth=2.5).
  - **Rationale**: Parallels the signed figure's SQ overlay, helping the reader see how the fitted primitive relates to the unsigned distance field.

### 3. Modify `fig_tsdf_signed_with_sq`

- [ ] Add the projected hand base positions (from step 1) as small grey/white points on the cross-section. Use `ax.scatter(x, y, s=1, alpha=0.3, color='white', label='ROI samples (iter 0)'`.
  - **Rationale**: Shows the spatial distribution of the motion model prediction samples that define the ROI. The viewer can see how the ROI bounding box (orange) encloses these samples, and how they relate to the object surface (SQ contour) and the signed distance field.
- [ ] Keep the existing point cloud slice and SQ contour overlay — the ROI samples are additive, not a replacement.
- [ ] If 1,000 points still cause visual clutter, switch to a 2D Gaussian KDE density overlay (hot colormap, low opacity) instead of individual points.
  - **Rationale**: A density heatmap conveys the same spatial clustering information without individual point overlap.

### 4. Regenerate Both Figures

- [ ] Run `python report/generate_figures.py` to re-generate `tsdf_unsigned_cross_section.png` and `tsdf_signed_cross_section.png`.
  - **Rationale**: Produces the ready-to-use figures for report insertion.

## Potential Risks and Mitigations

1. **Iteration 0 samples may be missing** — If the dump uses a column format older than 29-column (which includes `smc_iteration`), the iteration number won't be available.
   - **Mitigation**: Check `row_len` in the dump parser. If `smc_iteration` is unavailable, fall back to uniform random sampling within the ROI AABB as a synthetic approximation, with a note in the figure caption.

2. **20,000 projected points create visual overload** — Even a subset of 1,000 may clutter a 16×14 voxel grid.
   - **Mitigation**: Use 2D Gaussian KDE density heatmap instead of individual scatter points. The heatmap reveals the spatial concentration of samples while leaving the distance field readable underneath.

3. **No samples project onto the chosen Z-slice** — All iteration-0 hand positions might be above or below the middle Z-slice.
   - **Mitigation**: The projection ignores Z, showing all samples regardless of their Z-coordinate. This is fine for the purpose — we want to see the full set of sample positions relative to the ROI box.

---

## Alternative Approaches

1. **Full pipeline modification** — Add `_samples_for_roi` to the `DebugDump` struct and export them in the `.npz` file. This gives the exact ROI-generating samples (20,000 `SampledPose` instances with full 6-DOF) at the cost of Rust code changes. The iteration-0 proxy described above achieves the same visual result with zero pipeline changes.

2. **Synthetic approximation only** — If the scored_grasps approach doesn't work (e.g., incompatible dump format), generate 5,000 random points uniformly within the ROI AABB. This produces an acceptable visual stand-in, though it won't show the motion-model clustering behaviour that the real samples would exhibit.

3. **Separate inset figure** — Instead of overlaying the samples on the signed cross-section, create a small inset figure showing a top-down (X-Y) view of the ROI samples, ROI box, and point cloud. This keeps the signed cross-section clean while still providing the spatial context.
