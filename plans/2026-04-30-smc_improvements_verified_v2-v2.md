# Verified SMC Improvement Plan (Revised)

## Objective

Address Bug 1 (SMC losing best grasps) with targeted, verified fixes based on confirmed code analysis.

---

## Verified Findings

### Score Upper Bound (Confirmed)
All individual scores are bounded `[0, 1]`. The combined score formula at `planner.rs:24-37`:
```
combined = (0.5*prob + 1.0*alignment + 1.0*force_closure + 3.0*contact_score) / 5.5
```
Maximum = 5.5/5.5 = **1.0**. Score-weighted parent selection is safe — no single particle can dominate through extreme scores.

### sample_probability Contribution
Weight is 0.5/5.5 = **9.1%** of the combined score. It's not negligible but also not dominant. For a Tier 1 grasp with contact_score=1.0, alignment=1.0, force_closure=1.0:
- With prob=1.0: combined = (0.5 + 1.0 + 1.0 + 3.0)/5.5 = 1.0
- With prob=0.0: combined = (0.0 + 1.0 + 1.0 + 3.0)/5.5 = 0.909
- Difference: **0.091** — enough to change ranking between close candidates.

### What sample_probability Actually Represents
`predictor.rs:135-153`: It measures how likely the noise was under the motion model. For initial particles, this is meaningful — it reflects the twist prediction confidence. For resampled particles, the inherited value is meaningless because the particle's position comes from elite jittering, not from the motion model.

## Implementation Plan

### Task A: Track Overall Best Across Iterations (Output Fix)

- [ ] **A.1**: In `c_api.rs`, before the SMC loop (around line 419), add `overall_best: Option<(ScoredGrasp, SmcParticle)>`. After each iteration's `score_all_particles()`, find the iteration's best and update `overall_best` if it's better. Use `overall_best` for the final `ComputeOutput` at line 545+ instead of `select_best_grasps(&scored)`.
  - **Rationale**: Minimal fix that makes the ROS2 node always report at least as good as the debug dump's global best. Does not change SMC dynamics.

### Task B: Elite Injection (No Re-scoring)

- [ ] **B.1**: Modify `resample_around_elites` in `predictor.rs` to accept the elites sorted by score (descending). The function should reserve the top `n_elite_preserve = max(1, n_total * 0.05)` slots as direct copies of the best elites. These copies retain their existing `.score` and `.sample_probability`. The remaining `n_total - n_elite_preserve` particles are generated by jittered resampling as before. Add a config constant `ELITE_PRESERVE_RATIO: f64 = 0.05`.
  - **Rationale**: Top 5% (1000 of 20,000) guarantees the best-so-far survives unchanged. Their scores are already computed and are carried forward — no re-scoring needed. The SMC loop in `c_api.rs` already writes scores back into particles (line 238-240), so injected elites will simply be re-scored along with everyone else in the next iteration, which is correct since the TSDF hasn't changed.
  - **Important**: Since `score_all_particles` scores ALL particles in the array, the injected elites WILL be re-scored. This is actually fine — the TSDF and grasp geometry are the same, so they'll get the same score. The cost is just the scoring compute time for ~1000 particles. If this is a concern, we could skip re-scoring for particles that already have a non-zero score and were injected, but this adds complexity for minimal gain.

### Task C: Score-Weighted Parent Selection

- [ ] **C.1**: In `resample_around_elites`, replace uniform elite selection (`rng.random_range(0..n_elites)`) with score-weighted selection. Compute cumulative weights from elite scores (which are already in `[0, 1]`), then sample by drawing a uniform random number and binary searching the cumulative array.
  - **Rationale**: Better exploitation of the best-known regions. Since scores are bounded `[0, 1]`, no single elite can dominate excessively. An elite with score 0.8 is only ~4x more likely to be chosen than one with 0.2, which is a reasonable bias.

### Task D: Wrist Rotation Perturbation

- [ ] **D.1**: Add config constant `INITIAL_PROPOSAL_STD_WRIST: f64 = 0.3` (radians, ~17 degrees) in `config.rs`. This is the initial wrist perturbation std.

- [ ] **D.2**: Modify `resample_around_elites` to accept `proposal_std_wrist: f64` as a parameter. Instead of `rng.random_range(-π/2..π/2)`, perturb the parent elite's wrist rotation: `new_wrist = elite.wrist_rotation + rng.sample(Normal(0, proposal_std_wrist))`, clamped to `[-π/2, π/2]`.

- [ ] **D.3**: In the SMC loop in `c_api.rs`, compute `proposal_std_wrist = INITIAL_PROPOSAL_STD_WRIST * decay` alongside the existing v/omega proposal stds, and pass it to `resample_around_elites`.
  - **Rationale**: Preserves good wrist angles while still exploring. The decay schedule ensures convergence. Initial std of 0.3 rad (~17 deg) allows meaningful exploration; by iteration 9 it's `0.3 * 0.7^8 = 0.024 rad` (~1.4 deg) — tight enough for refinement.

### Task E: Grasp Type — Inherit with Small Mutation Probability

- [ ] **E.1**: Add config constant `GRASP_TYPE_MUTATION_RATE: f64 = 0.1` in `config.rs`.

- [ ] **E.2**: In `resample_around_elites`, change the grasp type selection logic. With probability `1 - GRASP_TYPE_MUTATION_RATE`, **inherit the parent elite's grasp type**. With probability `GRASP_TYPE_MUTATION_RATE`, sample from the weighted distribution as before (using `compute_grasp_type_weights`).
  - **Rationale**: This is a much better approach than pure weighted sampling. It means:
    - 90% of new particles explore refinements of their parent's grasp type (exploitation)
    - 10% explore other grasp types (exploration/mutation)
    - The weighted distribution still biases mutation toward promising types
    - A good cylindrical grasp will produce ~90% cylindrical children, who will refine it further
    - This directly addresses the type collapse problem without forcing artificial probability floors

### Task F: sample_probability — Set to 1.0 for Resampled Particles

- [ ] **F.1**: In `resample_around_elites`, set `sample_probability: 1.0` for all newly generated particles (both injected elites and jittered resamples).
  - **Rationale**: After careful consideration, here's my reasoning:
    - The motion model probability was meaningful for iteration 0 particles — it reflected how likely the hand would actually be at that position given the twist prediction.
    - For resampled particles, the position comes from elite jittering, not the motion model. Computing a "true" probability would require knowing the displacement from the current pose through the twist, which is complex and may not be meaningful.
    - Setting it to 1.0 effectively removes the probability term from the combined score for resampled particles, making the score purely about grasp quality (alignment + force closure + contacts).
    - This is actually desirable: after iteration 0, we want to rank grasps by quality, not by how "likely" the motion model says the position is. A great grasp at a low-probability position should still score highly.
    - The 9.1% weight of probability becomes a tiebreaker only for iteration 0, which is appropriate.
    - Alternative (recomputing from displacement): Possible but adds complexity. The displacement from current pose to resampled position is NOT a twist-model sample, so computing a meaningful probability is questionable. I recommend 1.0 for simplicity, and we can revisit if needed.

### Task G: Visualizer Iteration Cycling

- [ ] **G.1**: Add iteration cycling to `visualize_grasp_debug.py`. Add `[` and `]` keyboard shortcuts to decrease/increase the selected iteration filter. Add state variable `iteration_filter` (default: -1 = all iterations). When active, filter grasps to `smc_iteration == iteration_filter`. Display current iteration and its best score in the info text.
  - **Rationale**: Essential debugging tool for verifying SMC convergence behavior after the fixes.

## Risks and Mitigations

1. **Elite injection re-scoring overhead**: ~1000 extra scoring evaluations per iteration. With 20,000 particles already being scored, this is ~5% overhead. Acceptable.
   - Mitigation: None needed.

2. **Score-weighted parent selection + elite injection together may over-exploit**: The combination means the best elites are both preserved AND more likely to be parents.
   - Mitigation: The 10% grasp type mutation rate (Task E) and wrist perturbation (Task D) maintain enough diversity. The decay schedule also helps — early iterations have wide proposals for exploration.

3. **Setting sample_probability to 1.0 changes the scoring landscape for resampled particles**: Iteration 0 uses true probabilities; subsequent iterations don't.
   - Mitigation: This is actually an improvement. The probability term was distorting scores for resampled particles with inherited values. After this change, iteration 0 uses motion-model probability (correct), and later iterations use pure grasp quality (also correct).
